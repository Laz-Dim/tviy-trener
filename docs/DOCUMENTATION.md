# Технічна документація проєкту «Твій Тренер» (tviy-trener)

> **Проєкт:** Персональний веб-сайт та автоматизована платформа персонального тренера Іллі Поліщука (м. Львів).  
> **Продакшн адреси:**
> - **Версія 1 (Класичний атлетичний дизайн):** [https://tviy-trener.pages.dev](https://tviy-trener.pages.dev) (гілка `main`)
> - **Версія 2 (Преміальний темний бруталізм):** [https://tviy-trener-v2.pages.dev](https://tviy-trener-v2.pages.dev) (гілка `v2`)

## 1. Загальний огляд архітектури (JAMstack + Serverless)

Сайт реалізовано за концепцією **сучасного безсерверного JAMstack**:
- **Відсутність традиційного важкого сервера та реляційної БД:** немає потреби оплачувати VPS, налаштовувати Nginx чи підтримувати вразливі CMS (WordPress тощо).
- **Хостинг та Edge Compute:** **Cloudflare Pages** + **Cloudflare Pages Functions** (V8 Worker runtime на глобальній мережі Cloudflare).
- **База даних / State Storage:** 
  - **Git-as-a-CMS:** контент статей (`blog_posts.json`) та списки YouTube-відео (`videos_data.json`) зберігаються безпосередньо у Git-репозиторії.
  - **Cloudflare Workers KV (`OTP_KV`):** швидке key-value сховище на edge для тимчасових кодів авторизації Telegram OTP та рейт-лімітів за IP.
- **Статична генерація (SSG):** при зміні контенту генератор на Python генерує оптимізовані статичні HTML-сторінки кожної статті для максимальної швидкості та 100% SEO-індексації.
- **CI/CD та автоматизація:** **GitHub Actions** синхронізує відео з YouTube, регенерує статті блогу та автоматично виконує деплой на Cloudflare Pages.

## 3. Детальний опис компонентів системи

### 3.1. Клієнтська частина (Frontend)

1. **Головна сторінка ([`index.html`](../index.html)):**
   - Навігація зі скрол-фіксацією, мобільне бургер-меню з коректним закриттям при кліку на якірні посилання.
   - Секція філософії тренувань («Розумна сила», «Атлетизм», «Життя як марафон», «Дисципліна»).
   - Секція послуг: персональні заняття, схуднення, набір маси, бокс, ЗФП, раціон.
   - Галерея залу з повноекранним Lightbox.
   - **Динамічна відеотека:** рендериться з [`videos_data.json`](../videos_data.json) на клієнті через [`app.js`](../app.js). Підтримує фільтри «Все / Відео / Shorts», пагінацію («Показати ще») та модальний відеоплеєр.
   - **Динамічний прев'ю блогу:** завантажує останні статті з [`blog_posts.json`](../blog_posts.json).
   - Інтерактивна форма реєстрації на тренування.

2. **Сторінки статей блогу (`blog-*.html`):**
   - Генеруються скриптом [`generate_blog.py`](../generate_blog.py) на основі шаблону [`blog-template.html`](../blog-template.html).
   - Кожна стаття — це самостійний статичний HTML-файл з власним URL (наприклад, `blog-klassika-chi-kruzhka-tehnika-bokovogo-udaru.html`).
   - Містить повну SEO-оптимізацію: OpenGraph, Twitter Cards, JSON-LD `BlogPosting`.
   - Внизу кожної статті дублюється робоча форма запису на тренування.

### 3.2. Безпека та Serverless API ([`functions/api/`](../functions/api/))

Усі ендпоінти працюють як **Cloudflare Pages Functions** без сторонніх бібліотек, використовуючи нативний Edge Runtime та Web Crypto API.

#### 1. [`/api/register`](../functions/api/register.js) — Обробка заявок клієнтів
- **Валідація вхідних даних:** перевірка імені, суворий регекс для українського номера телефону `+38 (0XX) XXX-XX-XX`, фільтрація довжини повідомлення.
- **Дворівневий захист від спаму:**
  - **Honeypot:** невидиме для людей поле `<input name="website">`. Якщо бот його заповнює — запит негайно відхиляється.
  - **Edge Rate Limiting (Cloudflare KV):** обмеження за IP-адресою (`reg_rate:${ip}`) — не більше 3 заявок на 15 хвилин. Лічильник збільшується **виключно після** успішної валідації та надсилання.
  - **Client Rate Limiting:** додаткове блокування форми у `localStorage` браузера на 15 хвилин після 3 спроб.
- **Сповіщення в Telegram:** негайне паралельне надсилання повідомлення тренеру (`TELEGRAM_TRAINER_CHAT_ID`) та адміністратору (`TELEGRAM_ADMIN_CHAT_ID`) через Telegram Bot API з екрануванням спецсимволів MarkdownV2.

#### 2. [`/api/admin/send-code`](../functions/api/admin/send-code.js) — Безпарольний вхід (Telegram OTP)
- Вхід в адмін-панель реалізовано без використання статичних паролів, що унеможливлює злам через брутфорс.
- Доступ мають лише дозволені Telegram ID / юзернейми (тренер або адміністратор).
- Генерується 6-значний одноразовий цифровий код (OTP) з часом життя 5 хвилин (TTL = 300 сек у KV).
- Додано захист від спаму надсилання кодів: не більше 5 запитів на 10 хвилин з однієї IP-адреси.
- Код надсилається у приватний чат відповідного користувача в Telegram.

#### 3. [`/api/admin/verify-code`](../functions/api/admin/verify-code.js) — Перевірка коду та видача HMAC JWT
- Порівнює введений код із збереженим у KV `otp:${telegramId}`.
- Захист від підбору: максимум 3 спроби на один код, після чого код автоматично анулюється.
- **Криптографічний підпис HMAC-SHA256:** при успішній перевірці генерується захищений сесійний токен (JWT-сумісний формат `header.payload.signature`) за допомогою `crypto.subtle.sign('HMAC', ...)`.
- Час дії сесії: 24 години.

#### 4. [`/api/admin/posts`](../functions/api/admin/posts.js) — Управління блогом через GitHub API
- **`GET /api/admin/posts`:** завантажує актуальний `blog_posts.json` безпосередньо з репозиторію GitHub (`Cache-Control: no-store`), уникаючи застарілого CDN-кешу.
- **`POST /api/admin/posts`:** створення нової або оновлення існуючої статті:
  - Сувора криптографічна перевірка підпису HMAC-SHA256 токена (`verifySignedToken`). Недійсний або прострочений токен негайно відхиляється (`401 Unauthorized`).
  - Якщо завантажено зображення статті — конвертує та комітить файл у папку `img_new/` репозиторію через GitHub Contents API.
  - Оновлює масив у `blog_posts.json` та створює коміт у відповідну гілку (`main` або `v2`).
- **`DELETE /api/admin/posts`:** видалення статті за `slug` з комітом у GitHub.

### 3.3. Адміністративна панель ([`admin.html`](../admin.html) + [`admin.js`](../admin.js))

- Доступна за адресою `/admin.html`.
- **Авторизація:** введення Telegram ID → отримання коду у месенджері → введення коду → вхід.
- **Функціонал:**
  - Перегляд списку всіх нотаток з обкладинками, датами та категоріями.
  - Створення нових статей (автогенерація транслітерованого slug, вибір категорії, теги, прев'ю завантаженого фото до 2MB).
  - Повноцінне редагування існуючих статей (блокування зміни slug для збереження SEO-посилань, передзаповнення форми).
  - Видалення статей з підтвердженням.
  - Клієнтська валідація терміну сесії (`payload.exp`) та автоматичне скидання при `401 Unauthorized`.

### 3.4. Генератор контенту блогу ([`generate_blog.py`](../generate_blog.py))

Скрипт перетворює JSON-базу [`blog_posts.json`](../blog_posts.json) на готові статичні сторінки:
- Парсить Markdown у валідний семантичний HTML (`<h2>`–`<h6>`, списки `<ul>`/`<ol>`, посилання, виділення).
- Запобігає дублюванню тегів `<h1>` у тілі статті.
- Розраховує приблизний час читання статті.
- Вставляє зображення через безпечні відносні шляхи (працює однаково стабільно як на тестових доменах `.pages.dev`, так і на фінальному домені).
- Екранує лапки та спецсимволи у метатегах `{{TITLE}}`, `{{DESCRIPTION}}` та Schema.org JSON-LD.
- Автоматично перегенеровує актуальний [`sitemap.xml`](../sitemap.xml) для пошукових систем Google / Bing.

---

### 3.5. Відео-синхронізатор ([`get_videos.py`](../get_videos.py))

- Звертається до YouTube Data API v3 за каналом тренера `@tviy_trener`.
- Завантажує останні завантажені відео та Shorts, формуючи структуру [`videos_data.json`](../videos_data.json) (ID, назва, дата, тривалість, опис, посилання на мініатюру).
- Фільтрує та маркує ролики за типами (`video` vs `short`).

### 3.6. Автоматизація CI/CD ([`.github/workflows/update-site.yml`](../.github/workflows/update-site.yml))

Workflow запускається:
1. За розкладом щоранку о 06:00 UTC (`cron: '0 6 * * *'`).
2. При кожному пуші/коміті у файл `blog_posts.json` (наприклад, коли стаття збережена з адмін-панелі).
3. Вручну з вкладки Actions (`workflow_dispatch`).

**Що виконує пайплайн:**
1. Оновлює нові відео з YouTube (`python get_videos.py`).
2. Запускає `generate_blog.py` для створення HTML-сторінок та оновлення карти сайту `sitemap.xml`.
3. Комітить оновлені файли назад у GitHub із міткою `[skip ci]`.
4. Автоматично деплоїть проєкт на Cloudflare Pages за допомогою Wrangler:
   - для гілки `main` → у проєкт `tviy-trener`
   - для гілки `v2` → у проєкт `tviy-trener-v2`
5. Синхронізує свіжі відео та пости між гілками `main` та `v2`.

## 5. Інструкція: Перенесення сайту на домен `tviy-trener.com`

Коли ви будете готові підключити основний домен:

1. **Оберіть версію, яка буде головною:**
   - Якщо **Версія 1**: працюємо з проєктом `tviy-trener`.
   - Якщо **Версія 2**: працюємо з проєктом `tviy-trener-v2`.
2. **Підключення в панелі Cloudflare:**
   - Перейдіть у **Workers & Pages** → оберіть обраний проєкт.
   - Відкрийте вкладку **Custom domains** → натисніть **Set up a domain**.
   - Введіть `tviy-trener.com` та підтвердіть (Cloudflare автоматично оновить DNS-записи типу CNAME).
   - Повторіть для `www.tviy-trener.com`.
3. **CORS та безпека:**
   - В усіх функціях API домен `https://tviy-trener.com` та `https://www.tviy-trener.com` вже внесено у `allowedOrigins`. Жодних правок у коді не потрібно.
